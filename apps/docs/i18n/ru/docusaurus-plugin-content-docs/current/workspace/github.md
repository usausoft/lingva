# Интеграция проекта с GitHub

Интеграция с GitHub доступна как предварительная версия для разработки. Доступность
зависит от развёртывания. Суперадминистратор платформы управляет доступностью функций,
а владельцы и администраторы проектов настраивают своё подключение. Установка SDK не требует этой интеграции.

## Подключение репозитория {#connect}

1. Выберите проект в **Настройках** рабочего пространства и откройте **Интеграцию с GitHub**.
2. Установите или настройте GitHub App Lingva вашего развёртывания для выбранного репозитория.
3. Нажмите **Найти репозитории GitHub** и подтвердите свою учётную запись GitHub.
4. Выберите репозиторий, которым вы управляете, существующую базовую ветку,
   окружение проекта, настроенные локали и одну папку переводов.
5. Нажмите **Проверить и подключить** и пройдите новое подтверждение GitHub.

Первый провайдер поддерживает JSON-файлы `<folder>/<locale>.json`, например
`translations/en.json`. Другие форматы файлов и провайдеры пока не поддерживаются.
Приложению нужны права записи Contents, Pull requests и Actions, а также права чтения
Checks, Statuses и Metadata. Выбирайте только репозитории, которые хотите подключить.
Не требуется вставлять в Lingva закрытый ключ приложения или личный токен доступа.

## Создание pull request с переводами {#translation-pr}

Создайте и одобрите черновики через [проверку в рабочем пространстве](../workspace.md#translation-editing-and-review).
Выберите до 50 одобренных изменений из окружения и локалей подключения.
Lingva создаст pull request с переводами, сохранив остальные файлы репозитория
и значения переводов. Повторный выбор тех же изменений в рамках того же подключения
восстанавливает существующую операцию. Если изменений нет, новый коммит не нужен.

Создание pull request не публикует runtime-бандл, не сливает изменения, не развёртывает
приложение и не запускает отдельный workflow. Обычный CI для pull request работает
согласно настройкам вашего репозитория GitHub.

Обновите **Статус pull request и CI**, чтобы проверить результаты для текущего коммита PR.
Неизвестный статус, ожидание, ошибка и сообщённый успех различаются. Успешные проверки
не подтверждают выполнение правил защиты ветки, готовность к слиянию или развёртывание.
Перед слиянием проверьте изменения и обязательные проверки в GitHub.

## Явный запуск workflow {#workflow}

Дополнительная панель **Пользовательский workflow GitHub** запускает настроенный workflow
на базовой ветке подключения. Его объявление `workflow_dispatch` должно принимать
три параметра: `lingva_request_id`, `lingva_project_id` и `lingva_environment_id`.
Настройте и проверьте workflow, подготовьте запрос, затем явно подтвердите запуск.
Эти идентификаторы связывают запуск с запросом; они не являются учётными данными.

Принятие запроса GitHub не означает успешное выполнение workflow. Откройте ссылку на
запуск и проверьте результат. Перезагрузка или обновление существующего запроса проверяет
сохранённое состояние без повторного запуска. При неизвестном ответе сначала проверьте
GitHub и запрос; автоматические повторы могут дублировать работу.

## Отключение и восстановление доступа {#recovery}

**Отключить** удаляет привязку проекта, сохраняя существующие pull request
и установку GitHub App. История интеграции содержит поддерживаемые операции
без содержимого переводов и учётных данных.

Приостановка приложения или удаление доступа к репозиторию отзывает затронутые подключения.
Восстановление доступа не подключает проект автоматически. Найдите репозиторий
повторно и пройдите новую проверку перед синхронизацией.
Если функция отключена, попросите суперадминистратора проверить политику и готовность развёртывания.
Администраторы проектов не могут включить глобально отключённую функцию.
