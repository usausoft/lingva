# Начальный проект React с платформой

Рекомендуемый шаблон для подключения React к Remote в Lingva:

1. создайте учётную запись Lingva и проект в рабочем пространстве
2. установите SDK и CLI, затем войдите через `lingva auth login`
3. создайте конфигурацию Remote и настройте SDK-ключ только для чтения
4. подготовьте переводы, проверьте их через `lingva check` и отправьте на платформу
5. проверьте доставку пакета в приложении и управляйте переводами в рабочем пространстве

## Создание начальных файлов интеграции {#scaffold-the-integration}

Запустите автоматическую настройку из корня принадлежащего клиенту приложения
React:

```bash
pnpm add @lingva/react
pnpm add -D --allow-build=@lingva/cli @lingva/cli
pnpm lingva auth login
pnpm lingva init --mode remote --sdk react
pnpm lingva check
```

`lingva init` находит проекты вошедшего пользователя и предлагает выбор только
при неоднозначности. Откройте выбранный проект в `/app/projects/<project-id>`,
чтобы проверить сформированные значения и создать ключ доставки только для
чтения, если приложение получает переводы с платформы во время выполнения.

## Проверка локального состояния {#verify-local-state}

```bash
pnpm lingva check
```

Автоматическая настройка выше создаёт переносимый `lingva.config.yaml` и
типизированный адаптер среды выполнения React `.lingva/generated/runtime.ts`,
а файлы переводов располагаются в `.lingva/translations/{locale}.json`.
Оставляйте YAML основным источником конфигурации CLI.

Пример в репозитории `examples/hosted-react-starter`, напротив, использует
написанный вручную `lingva.config.ts` и зависимости рабочей области. Это пример
реализации внутри репозитория, а не самостоятельный шаблон для копирования и
установки. Адаптер npm поддерживает его доверенную исполняемую конфигурацию;
не создавайте рядом дублирующий корневой YAML-файл.

## Вход для команд платформы {#sign-in-for-hosted-commands}

Скопируйте команду входа CLI из **Consumer application setup**. CLI получает
публичные метаданные OAuth выбранного окружения из платформы:

```bash
pnpm lingva auth login
# Stage: pnpm lingva auth login --platform-url https://stage.lingva.dev
```

На локальных машинах разработчиков предпочитайте вход через браузер служебным
токенам. Служебные токены следует оставлять для CI и серверных обработчиков
панели управления.

## Отправка для доставки с платформы {#push-hosted-delivery}

```bash
pnpm lingva push \
  --output-dir .lingva/artifacts/push \
  --api-url "<copy publish URL from Lingva>" \
  --invalidate
```

Команда отправляет локальные переводы на платформу для доставки и сохраняет
ответ сервера в `.lingva/artifacts/push/publish-response.json`. Она не записывает
локальные файлы пакетов локалей; для этого используйте `lingva bundle` или
`lingva publish` без адреса сервиса. SDK-ключ только для чтения не может
авторизовать эту операцию записи.

## Работа в приложении {#app-path}

После создания проекта в панели управления:

- откройте `/app/projects/<project-id>`, чтобы скопировать параметры настройки и создать SDK-ключ доставки только для чтения
- откройте `/app/settings`, чтобы создавать или отзывать приглашения в проект
- откройте `/app/translations`, чтобы просматривать и изменять черновики переводов
- откройте `/app/delivery`, чтобы изучать историю публикаций и операции доставки

## Зачем нужен этот начальный проект {#why-this-starter-exists}

Этот шаблон намеренно небольшой. Он избегает выдуманных процессов работы с
API-ключами и сосредоточен на продуктовом пути, который уже можно проверить:
конфигурация, типизированная среда выполнения React, аутентификация CLI,
публикация на платформе, сброс кеша и управление приглашениями.
