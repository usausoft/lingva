# Доставка пакетов через CDN

Lingva поддерживает загрузку **пакетов переводов** из CDN во время работы приложения. SDK опубликованы в npm как пакеты ESM и CommonJS. Сейчас Lingva не поставляет UMD-файл с глобальным объектом браузера для обычного тега `<script>`.

Установите `@lingva/js` из npm и настройте URL доставки через CDN:

```ts
import { configureLingvaJs, createLingvaJsRuntime } from '@lingva/js';

configureLingvaJs({
  projectId: 'website',
  environment: 'dev',
  locale: 'en',
  fallbackLocale: 'en',
  apiKey: '<delivery:read SDK key from Consumer application setup>',
  delivery: {
    mode: 'cdn',
    url: 'https://example.lambda-url.eu-west-1.on.aws/bundles/{projectId}/{environment}/latest/{locale}.bundle.json',
  },
});

export const lingva = createLingvaJsRuntime();
await lingva.loadLocale('en');
console.log(lingva.tSync('welcome.title'));
```

Загрузите каждую облачную локаль перед синхронным чтением. `setLocale` меняет выбранную локаль, но не загружает её в обычном JavaScript. Для асинхронного поиска используйте `await lingva.t(...)`; уничтожайте среду выполнения при завершении жизненного цикла её владельца. Глобальный `configureLingvaJs` подходит только для настроек одного проекта в браузере; серверные запросы должны передавать явную конфигурацию в отдельную среду выполнения каждого запроса.

Клиентам следует скопировать полный URL пакета из раздела **Consumer application setup** на странице `/app/projects/<project-id>`; доступ к AWS или поиск выходных данных инфраструктуры не нужен. Конечная точка доставки поддерживает следующие маршруты текущих пакетов:

```text
GET {deliveryBaseUrl}/bundles/{projectId}/{environment}/latest/manifest.json
GET {deliveryBaseUrl}/bundles/{projectId}/{environment}/latest/{locale}.bundle.json
```

URL доступны публично, но запросам нужна аутентификация. Среда выполнения передаёт SDK-ключ с правом чтения в заголовке `x-api-key`. Браузер может просмотреть этот ключ, поэтому выдавайте только право `delivery:read`; никогда не раскрывайте учётные данные администрирования проекта, редактирования или публикации. Приложения с более строгими требованиями должны обращаться к доставке через собственный сервер с аутентификацией.

Попросите администратора рабочего пространства разрешить адреса ваших браузерных приложений перед загрузкой пакетов в браузере. Нативные и серверные клиенты не ограничены браузерным CORS. Публикация и инвалидация требуют отдельных прав записи.

URL среды выполнения может содержать идентификаторы проекта, окружения, локали и публикации, поддерживаемые другим сервером доставки. Политики кэширования, заголовки аутентификации и различия локального режима и CDN описаны в разделе [Настройка](./configuration.md).

Отдельную браузерную сборку можно добавить позже как самостоятельный проверенный артефакт пакета. Пока используйте интеграцию через пакет вместо URL неопубликованного `dist/index.umd.js`.

Для мобильного использования тех же JSON-артефактов см. [Использование нативных пакетов](./native-bundles.md).
